# Закуп подсолнечника — прототип (Этап 1 / MVP)

Внутренний инструмент менеджера по закупу сырья для МЭЗ (г. Семей).
Реализует Этап 1 из [PRD](../prd.md): база КХ, запуск опроса, сбор и разбор
ответов, дашборд из 4 блоков и детальная таблица. Интерфейс на русском,
адаптивен под телефон.

## Запуск

Это статичное веб-приложение без сборки. Откройте любой статический сервер
из папки `zakup/`:

```bash
cd zakup
python3 -m http.server 4178
# затем http://localhost:4178
```

Данные хранятся в `localStorage` браузера (ключ `mez_zakup_v1`).
Кнопка «Сбросить демо-данные» в Настройках возвращает исходный набор.

## Что реализовано

- **База КХ** — добавление/редактирование/деактивация, теги, заметки.
  Расстояние до завода считается автоматически по координатам (гаверсинус ×1.25
  как дорожное приближение), пересчитывается при смене точки завода в Настройках.
- **Запуск опроса** — «отправляет» шаблонное сообщение всем активным КХ,
  ведёт статус *отправлено / ответили*.
- **Сбор и разбор ответов** — свободный текст из WhatsApp парсится в 4 поля
  (объём, влажность, сорность, масличность, цена); менеджер правит в один клик.
  Неполные ответы помечаются.
- **Дашборд**: KPI (объём, ответы, средняя и средневзвешенная цена) +
  4 блока (расстояние, количество, качество, цена) + сортируемая/фильтруемая
  таблица с быстрым переходом в WhatsApp.
- **Настройки** — целевая цена, приёмочные нормы, координаты завода, радиусы.

## Что смоделировано (заглушки)

- **Рассылка WhatsApp** не отправляется реально — меняется статус опроса.
- **Входящие ответы** приходят по кнопке «Симулировать ответы» из
  демо-набора `SEED_INCOMING` в [seed.js](seed.js).

## Подключение реального WhatsApp Business API (следующий шаг)

PRD оставляет выбор провайдера открытым (Green API / 360dialog / Wati и др.).
Точки интеграции в коде:

- **Исходящая рассылка** — функция `launchSurvey()` в [app.js](app.js):
  вместо простой смены статуса вызвать отправку утверждённого шаблона через API
  провайдера по списку `activeFarms()`.
- **Входящие** — функция `simulateResponses()` заменяется обработчиком вебхука:
  по входящему сообщению найти КХ по номеру, прогнать текст через `parseMessage()`
  и записать в `state.responses`.
- **Парсер** `parseMessage()` уже извлекает числа и ключевые слова из свободного
  текста; для Этапа 2 здесь же подключаются интерактивные кнопки/списки.

Для продакшена потребуется бэкенд и БД (PRD §8) — текущий `localStorage`
заменяется на серверное хранилище опросов и ответов.
